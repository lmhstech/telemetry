The standard being audited against

This estate is unusual in having written its own rules down, which makes it auditable rather than a matter of opinion. Three documents set the bar, and the findings below are all places where code and stated policy disagree.

  • Privacy policy §4 — "What we never collect": email addresses, legal names, student ID numbers, home address, date of birth.
  • Privacy policy §6 — the complete list of third-party services that may see estate data.
  • Privacy policy §10 — FERPA: education records are held against an anonymous identifier, never a named student.
  • auth/INTEGRATING.md — one identity provider, PKCE mandatory, RS256 pinned, and "keeping your own password field as a fallback → delete it".

Findings

Ordered by severity. Each is a concrete disagreement between what the code does and what the estate has published about itself.

C-1 Student names, district ID numbers and emails are collected and stored classroom-inventory

The kiosk registration flow asks for and stores exactly the three categories the privacy policy says are never collected. This is also the organisation's only public repository, so the schema is world-readable as a statement of what the programme does.

Evidence 
db/init.js:26
CREATE TABLE students (
  student_id TEXT UNIQUE NOT NULL,   ← district student ID
  full_name  TEXT NOT NULL,          ← legal name
  email      TEXT                    ← email address
);

routes/kiosk.js:114  const { student_id, full_name, email } = req.body;
views/kiosk/index.ejs:263  <label>School Email (optional)</label>
Why it matters

Checkout records keyed to a named student are education records under FERPA. Every other app in the estate deliberately avoids this — velri joins names client-side from a teacher's USB drive precisely so the server never holds one. This app is the single exception, and it is the public one.

Fix

Replace the students table with the estate's anonymous username, issued by auth.lmhstech.com, and drop full_name and email entirely. If a human-readable name is needed at the kiosk, follow velri's pattern and join it client-side. Until then, either make the repository private or strip the columns.

C-2 Authentication runs through Supabase, not the estate's identity provider 240ai

The module's own docstring says it "integrates with auth.lmhstech.com" and then describes that host as a "Supabase OAuth 2.1 IdP" — two different systems conflated into one sentence. The code verifies tokens against a Supabase project, and authorises users by checking for an @lmhstech.com email address, which the estate states does not exist for anyone.

Evidence 
backend/middleware/auth.py:56
email = user.get("email", "")
if not email.endswith("@lmhstech.com"):
    raise HTTPException(403, "Only @lmhstech.com accounts are allowed")

backend/middleware/auth.py:79
https://kuvqhmmtzigexxfoyeue.supabase.co/auth/v1/user
Why it matters

Supabase is a third-party processor holding account data, and it does not appear in the privacy policy's §6 list of services. llm.lmhstech.com is listed there as a site students sign in to — so the policy describes a sign-in that is not the one actually running. It also means a second system holds credentials, which is the exact thing central sign-on exists to prevent.

Fix

Repoint to auth.lmhstech.com using the OIDC client pattern already proven in fleet/src/lib/oidc.js, and authorise on the role claim instead of an email domain. If Supabase must stay for a transition period, it needs adding to §6 of the privacy policy first.

H-1 Verified-session cache never expires, so revocation does not take effect 240ai

Token verification results are cached in a plain dictionary keyed by a hash of the token, with no TTL and no size bound. Once a token has been verified, it is treated as valid for the lifetime of the process — after it expires, and after the account is disabled.

Evidence 
backend/middleware/auth.py:71
_jwt_cache: dict = {}
...
if cache_key in _jwt_cache:
    return _jwt_cache[cache_key]     ← no expiry check
...
_jwt_cache[cache_key] = user         ← never evicted
Fix

Store an expiry alongside each entry and honour the token's own exp; cap the cache size. A short TTL (60s) keeps the performance benefit without outliving a revocation by more than a minute.

H-2 Shared staff registration secret is printed to the console on every boot classroom-inventory

REGISTRATION_CODE is the secret that lets someone create a staff account. It is written to stdout each time the server starts, so it lands in terminal scrollback, process managers, and any log aggregation the host does.

Evidence 
server.js:45
console.log(`   Registration code: ${process.env.REGISTRATION_CODE}`);
Fix

Delete the line. If a boot-time reminder is wanted, print whether it is set, never its value.

M-1 Local password auth runs in parallel with central sign-on classroom-inventory · kiosk-app

Both apps maintain their own users tables with bcrypt password hashes and their own JWT issuance. INTEGRATING.md addresses this directly: "Keeping your own password field as a fallback → Delete it. The point of central sign-on is that only one system holds passwords."

Fix

Register both at auth.lmhstech.com/admin and replace the local login. This also resolves C-1's identity half, since the IdP supplies the anonymous username these apps need.

M-2 Session cookies are not marked Secure classroom-inventory · kiosk-app

Cookies are set httpOnly and sameSite: 'strict', but without secure: true — so the browser will send them over plain HTTP. The estate's other apps set it (see fleet/src/lib/http.js, which hardcodes Secure).

Evidence 
routes/auth.js:32
res.cookie('token', token, {
  httpOnly: true,
  maxAge: 7 * 24 * 60 * 60 * 1000,
  sameSite: 'strict'          ← no `secure: true`
});
Fix

Add secure: true in any non-local environment.

M-3 Unauthenticated API exposes equipment serials and theft status classroom-inventory

/api/* is deliberately open — the file says "No auth needed — only returns non-sensitive item data". It returns item names, brands, models and a stolen flag. That is a defensible call for a kiosk on a closed lab network, but it is worth making deliberately rather than by comment.

Fix

Give the Pi kiosk a shared bearer key — the same pattern the new telemetry ingest uses — or confirm in writing that the endpoint is LAN-only and add a bind-address check.

L-1 Four repositories have no .gitignore cds · main-settings · main-site · powerpoints-1

None currently contains a leaked secret — this is preventative. main-site is the one that matters, since it is actively edited and now carries a telemetry config file.

Fix

Add a minimal .gitignore covering .env, .dev.vars, node_modules/ and .DS_Store.

L-2 Linked media page is an empty file main-site

media/index.html is 1 byte. legal/media.html describes the photo and video takedown process, and a reader following through to the media page gets a blank screen.

Fix

Populate it or remove the route so the takedown path does not dead-end.
